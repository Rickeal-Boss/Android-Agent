## 1. 本版本的已知取舍（**不要当 bug 报**）

这一节请先看。下面是**有意为之**的设计决定，报上来会被退回，但会浪费你一轮沟通。

| 现象 | 为什么是有意的 | 出处 |
|---|---|---|
| **顶栏不是胶囊**，是整条全宽 | 全宽顶栏做成胶囊会把标题挤进两端圆角里，标题会被裁 | `GlassTopBar.kt:47`（`fillMaxWidth`，无 `capsule`） |
| **输入框不是胶囊**，且观感与其他玻璃件不同 | 输入框**刻意不走** `LiquidGlassSurface` 门面——门面的按压反馈只由 `onClick` 驱动，而输入框没有 onClick，它的"变实"必须走**聚焦**这条 | `GlassTextField.kt:62-65` |
| **滑块 / 开关的 thumb，静止时是白色实心**，按下才变透明露出折射 | 对齐 Kyant0 原实现。**不是**"白色没做透明"的 bug | `GlassSlider.kt:387`、`GlassSwitch.kt:259` |
| **卡片 / 对话框 / 对话气泡没有色散**（边缘没有彩虹色带） | 色散要 7 次采样、约 7 倍开销。气泡是全 App 最长的列表，一屏十几条，开着必掉帧。**性能取舍，不是效果缺失** | commit `b63cca7` |
| **色散只出现在小控件上**（滑块 / 开关的 thumb） | 面积小才扛得住 7 倍开销，这是本轮刻意保留的 | `GlassSlider.kt:353`、`GlassSwitch.kt:188` |
| logcat 里出现 `LiquidGlass: lens 跳过折射：shape=... 不是 ...` | **正常且无害**。传非 `Capsule` 形状本身合法，只是拿不到折射优化。级别是 `Log.d`，release 包会被 R8 整条删掉 | `Lens.kt:126-131` |
| **设置页按在开关 / 设置行上滑不动页面** | **预期行为，不要报**。整行都是手势区、`fillMaxWidth()` 全宽吃满，父级只能从行与行之间的空白起手。用户早已习惯"按在行上没反应、按在空白才滚" | `GlassSettingRow.kt:59` / `:82`（`fillMaxWidth`） |
| **在按钮上起手滑列表，要先滑一小段才起滚** | **预期代价，不是 bug**。轴向判定需要几 px 位移才能确定方向，所以起滚会有极短的延迟 | 见 §4.2 |

> 另有一条**本轮已变更**、容易误判的：
> **底栏页签项是跟手的**（按住会跟着手指位移、沿拖动方向拉长，松手回弹）。
> 早期版本不跟手，后来在 NavBar/NavRail 改造里补上了。
> 所以 §7 的"拖动跟手"**是要求实现的**，不是取舍。若你手上的包不跟手，那是 bug，请报。

### 1.1 已知问题（**是缺陷，但本轮未修** —— 可以报，但不必重复报）

上面那张表是"有意为之、别报"；下面是**确实存在的问题**，只是本轮没纳入修复范围。
报的时候请注明"已知问题"，省一轮沟通。

|---|---|---|
| **开关没有名字** —— TalkBack 只念「开关，开 / 关」，不会念出「背景模糊」等 | `GlassSwitch` **没有 `label` 参数**。设置页三个开关（背景模糊 / 噪点微纹理 / 减弱动效）都受影响 | `GlassSwitch.kt:73`（函数签名无 `label`） |

## 2. 装包第一眼：整体观感

不点任何东西，先把 App 打开看 5 秒。这一步判断的是"玻璃是不是玻璃"。

### 2.1 胶囊轮廓
- **操作**：进设置页，看那些按钮 / Chip / 分段项的两端
- **预期**：两端是**正半圆**，不是被压扁的跑道形。上下边缘平直，只在两端收圆
- **不合格时**：报"胶囊被压扁"，附截图。指向 `liquid/shapes` 的 `Capsule` 与 `cornerRadius` 的取值关系

### 2.2 折射与色散是否可见
- **操作**：找一个**小控件**（设置页的开关、滑块），看它的 thumb 边缘
- **预期**：
  - 能看到**折射**——边缘有一圈"厚度渐变带"，像一块有厚度的玻璃而不是一张半透明贴纸
  - 小控件的 thumb 上能看到轻微**色散**（边缘彩虹色）
  - **大面积**的卡片 / 气泡**没有**色散（见 §1，这是有意的）
- **不合格时**：
  - 完全没有折射 → 可能是 API 31~32 降级（见 §9），或背景模糊开关被关掉了
  - 小控件也没有色散 → 检查 `GlassSlider.kt:353` / `GlassSwitch.kt:188` 的 `chromaticAberration = true` 是否被改成 `false`

### 2.3 壁纸光斑
- **操作**：换一张**有明显明暗变化**的壁纸，回 App 看玻璃后面的背景
- **预期**：玻璃后面能看到壁纸的内容与光斑，且被"提鲜"过（饱和度略高），不是一片死板的灰
- **不合格时**：背景一片纯色 / 玻璃像素级透出壁纸（等于玻璃消失）→ 指向 `LocalBackdrop` 与 `enableBackdropBlur` 的联动

## 3. 点三个开关（**验证 P1-1：点了要切换**）

这是本轮**最重要**的一条。修复前"点开关只是抖一下弹回去，状态不变"——真机第一眼就会踩。

- **操作**：设置页 → 外观分区，依次点这三个开关：**背景模糊**、**噪点微纹理**、**减弱动效**
  1. 每个开关**连点 10 次**，每次都要切换
  2. **手指故意带 1~3px 的横向位移**再松手（真机上没有绝对静止的点击，这一条最能暴露回归）
  3. 按住 thumb **拖过一半**再松手，看是否吸附到那一侧
- **预期**：
  - 连点 10 次 → **10 次都切换**，一次都不能"抖一下弹回原状态"
  - 带 1~3px 位移 → **仍然切换**
  - 拖过半松手 → 吸附到手指那一侧，不会弹回
- **不合格时的排查指向**：
  - **"点了不切换"** → 判定拖动的阈值回归了。查 `GlassSwitch.kt` 里的 `draggedX` 累积与 `touchSlopPx`（应为 `8.dp.toPx()`）。
    验收硬标准：该文件里**不应出现** `dragAmount.x != 0f`（这是修复前的写法，只要横向位移非零——**亚像素也算**——就误判成拖动）
  - **"一次点击回调了两次"** → 纯点击的提交被重复走了。正确做法是纯点击交给外层 `toggleable` 统一提交，
    拖动的提交在 `onDragStopped` 里，两者互斥
  - **"手指带位移就不切换"** → 阈值被调得过大，或又退化成"位移非零即拖动"
  - **"轻点有反应，但位移一小点就完全没反应"** → 拖动手势**一动就消费事件**了，会把外层
    `toggleable` 的点击一起取消。正确做法是给手势传 `consumeSlopPx = touchSlopPx`——
    **只有真拖动才消费**，抖动 1px 时点击原样交给 `toggleable`

## 3.5 逐个点所有玻璃控件（**验证 P0：点了必须有反应**）

**本轮最容易漏、也最致命的一条。** 修复前"所有玻璃按钮 / 分段项 / 页签点了都没反应"——
CI 和静态审查都发现不了，只有真机能复现。

> **为什么 §3 测了开关还不够**：开关走的是 `DampedDragAnimation`（`GlassSlider` 同），
> 而下面这批走的是 **`InteractiveHighlight.gestureModifier`** —— 是**另一条代码分支**。
> 只修一条的话，**另一批会全挂而开关好好的**。两条都要验到。

- **操作**：依次点击下面这些，**每个都点 5 次**，且**手指故意带 1~3px 抖动**再松手
  （真机没有绝对静止的点击，这一条最能暴露回归）：
  1. 设置页里的**按钮**与 **Chip**
  2. 设置页里的**分段项**（每个分段都点一遍）
  3. 悬浮按钮 **Fab**（若有）
  4. 设置页里的**每一行**（可点击的设置行）
  5. **顶栏的图标按钮**（返回箭头、标题旁的图标等）
  6. **底栏的三个页签**（聊天 / 模型 / 设置）—— 点了要真的切页
  7. 宽屏 / 横屏下的**侧栏页签**

  > ⚠️ **第 5 项（顶栏）和前面几项结构不同，排查时别找错地方**：
  > 按钮 / Chip / 分段项 / Fab 的 `clickable` 和 `gestureModifier` **在同一个文件里**
  > （如 `GlassButton.kt:78` 与 `:115`），clickable 在外、手势在内。
  > 但 **`GlassTopBar.kt` 里没有 `clickable`**——它的 `navigationIcon` / `actions`
  > 是 `@Composable` 插槽，`clickable` 由**调用点**挂上去（如 `ChatScreen.kt:93`
  > `.clickable(onClick = onOpenModels)`），而且层级是**反的**：`gestureModifier` 在
  > **外层**（顶栏容器），`clickable` 在**内层**（插槽里的图标）。
  > 失败模式一样，但**去 `GlassTopBar.kt` 里找 `clickable` 会一无所获**。
- **预期**（两条必须**同时**成立，只有一半就是改错了方向）：
  1. 每一次点击都要**有响应**——状态变化 / 页面切换 / 回调触发
  2. **跟手形变照常出现**——按住会跟着手指动、松手回弹

  > 第 2 条不是顺带提的：这个修复只改了"什么时候把事件标记为已消费"，**没动**跟手位移
  > 的计算。所以如果点击修好了但跟手没了（或反过来），说明改的方向不对——
  > 比如为了修点击直接把 `consume()` 删掉，那父级滚动就会来抢手势。
- **不合格时的排查指向**：
  - **"点了完全没反应，但跟手形变还在动"** → 手势**一动就消费事件**，把外层 `clickable`
    的按压取消了。正确做法是**累积**位移越过 touch slop 才 `consume()`（不是按单帧 delta 判）——
    见 `InteractiveHighlight.kt` 的 `gestureModifier`
  - **"只有开关能点，按钮 / 页签不行"** → 只修了 `DampedDragAnimation` 那条分支，
    漏了 `InteractiveHighlight` 这条。见上面那段说明
  - **"轻点有反应，稍微动一点就没反应"** → slop 没生效，或阈值被写死成 0
  - **"点击好了但页面一划就跟着动 / 滚不动了"** → 修过头了：`consume()` 被删干净，
    父级滚动抢不到手势

## 4. 设置页滑块（玻璃质感强度）

- **操作**：设置页 → 外观 → 「玻璃质感强度」滑块（范围 0.5~1.5）
  1. **拖动**：按住 thumb 左右拖，看数值是否连续变化
  2. **松手落盘**：拖到一个明显的值（比如 1.30），**退出设置页再进来**，看是否还在
  3. **点轨道跳转**：点轨道中间某个位置，看 thumb 是否跳过去
  4. **行高是否够按**：用拇指点，看是否容易点偏
- **预期**：
  - 拖动时数值**连续变化**（不是一跳一跳）
  - 退出重进后**值仍在**（拖动期间只改内存，松手才落盘一次——这是刻意的，避免每帧写盘掉帧）
  - 点轨道中间 → thumb 跳到该位置
  - 轨道虽然只有 6dp 高，但**上下有 48dp 的触摸区**，不该点偏
- **不合格时的排查指向**：
  - **"值没保存"** → 落盘时机不对。检查 `onValueChange`（只 preview，改内存）与 `onValueChangeFinished`（commit，写盘）是否分开了
  - **"拖动时明显掉帧"** → 松手前的每帧写盘回来了。该项值变化会触发全 App 重组 + 每个玻璃节点重画，再叠加写盘必然卡
  - **"点轨道中间没反应 / 很难点中"** → 触摸目标没生效。正确做法是 48dp 的触摸区挂在**外层**，手势也挂外层；
    若手势挂在 6dp 的轨道本体上，上下留白就是"看得见点不到"

### 4.1 从滑块上纵向滑，页面要能滚（**高频动作，别漏**）

这是真机上非常常见的动作：参数面板内容多、必须滚动，用户**一定会从滑块上滑过去**。
它和 §4 那几条测的不是一件事——那里测"滑块能不能调"，这里测"**滑块会不会把列表的滚动吃掉**"。

> **为什么值得单独测**：全 App 共 **13 个滑块**，全部位于可滚动容器里
> （`SettingsScreen:78` / `ChatParamsPanel:47` 都是 `verticalScroll`）——
> SettingsScreen 5 个、ChatParamsPanel 7 个、EndpointsScreen 1 个。
> 只要滑块的拖动手势在 touch slop **之前**就把事件消费掉，父级滚动就收不到手势。

- **操作**：
  1. 设置页 → 手指**按在滑块上**（不是滑块旁边的空白），**纵向**向上 / 向下滑动
  2. 对话页 → 打开参数面板（温度 / top_p 那屏，滑块最密集）→ 同样**按在滑块上**纵向滑
  3. 再试一次：按在滑块上纵向滑**一小段（< 1cm）**后松手
- **预期**：
  - 页面**正常滚动**——纵向滑动归列表，不该被滑块吃掉
  - 滑块的值**不应明显跳变**（纵向滑的横向分量 ≈ 0）
  - **横向**拖仍然立即响应、连续变化（这条是防"修过头"，见下）
- **不合格时的排查指向**：
  - **"按在滑块上滑不动页面"** → 滑块的拖动手势在 touch slop 之前就消费了事件。
    定位 `GlassSlider` 里构造 `DampedDragAnimation` 时**有没有传 `consumeSlopPx`**——
    **没传就是默认 `0f`，等于"动一个像素就消费"**（`DampedDragAnimation.kt:68`）。
    对比 `GlassSwitch.kt:137` 的 `consumeSlopPx = touchSlopPx`（8dp），
    开关传了、滑块没传，这就是两者行为不一致的原因
  - **"现在能滚了，但横向拖动前面一小段不跟手"** → **修过头了**：直接传 touch slop
    会让横向前 8dp 也不响应。正确做法是**只累加主轴位移**再判阈值，
    而不是把纵向 / 横向的欧氏距离一起累加
    （现状是 `accumulated += dragAmount.getDistance()`，见 `DampedDragAnimation.kt:134`）

### 4.2 模型页：按在按钮 / chip 上纵向滑，页面要能滚（**P0，覆盖面最大**）

**这是比 §4.1 更大的面，别只测滑块就收工。**

> **为什么模型页是最大面**：`ModelsScreen.kt:136` 是 `LazyVerticalGrid`，而每张 `ModelCard`
> 里有 **4 个 `GlassButton`**（`ModelCard.kt:160/174/190/203`）**外加一堆 `GlassChip`**
> （体积 / 量化 / 家族 / 能力位等，一张卡最多能到 9 个）。
> 这是全 App 唯一"**在可滚容器里塞多个小按钮**"的地方，而模型页是主页面之一 ——
> 用户在按钮上起手滑列表是**最高频**动作。
>
> 对照：设置页的 `GlassSettingRow` **不受影响**（整行全宽吃满手势区，见 §1）——
> 那边滑不动是预期的，**不要报**。

- **操作**：
  1. 进**模型页**（卡片网格，主页面之一）
  2. 手指**按在某张卡片上的按钮**（卸载 / 加载 / 探测 / 删除任一）**纵向**滑动
  3. 同样在卡片里的 **chip** 上试一次
  4. 再试：按在卡片**空白处**（按钮之间的区域）纵向滑 —— 这个应当**一直**能滚
- **预期**：
  - 按在按钮 / chip 上纵向滑 → **页面应当滚动**，不该被按钮吃掉
  - 按在卡片空白处滑 → **一直**能滚
  - **横向**拖按钮仍然有**跟手形变**（玻璃跟着手指跑、沿拖动方向拉长）——
    这条不能丢，它是本轮的核心视觉特性
- **不合格时的排查指向**：
  - **"按在按钮上滑不动，但按空白处能滑"** → `InteractiveHighlight` 的**轴向锁定没生效**。
    定位 `liquid/interactive/InteractiveHighlight.kt` 里 `accumulatedY > accumulatedX`
    那个分支（`:164-165`）——应当是 **`break`**，不是 `continue`、**也不是只跳过 `consume()`**。

    > 为什么必须是 `break`：`verticalScroll` / `LazyColumn` 的 `startDragImmediately = false`，
    > 父级只在 **Main pass** 消费，而 Main **自下而上**，子级永远先拿到未消费事件。
    > 只跳一次 `consume()` 的话，父级开滚后子级仍会继续 `onDrag` 把事件吃掉。
    > `break` 后 `awaitEachGesture` 等抬手才重启，一次解决。
  - **"现在能滚了，但横向拖动不跟手了"** → **修过头了**：`break` 条件写成了
    "只要有位移就 break"。正确是**只在纵向累积更大时 break**（`accumulatedY > accumulatedX`），
    横向要保住消费 + 跟手 —— 横向消费的作用是取消外层 `clickable`，
    避免拖动后松手误触发 `onClick`
  - **"要先滑一小段才起滚"** → **这是预期代价，不是 bug**，见 §1。
    轴向判定需要几 px 位移才能确定方向
  - **"chip 的占位比预期宽 / 挤开了旁边的控件"** → 见下面这条观察项

> **观察项（当前无调用点依赖，但值得留意）**：`GlassChip` 的
> `Arrangement.spacedBy(6.dp, Alignment.CenterHorizontally)`（`GlassChip.kt:87`）
> 带了对齐参数后会**吃满父级宽度**；chip 家族本身没有 `fillMaxWidth` 的写法，
> 所以放进 `Row` 的 `weight` / `spacer` 布局时，实际占位会和加对齐之前不一样。
> 如果发现 chip 比预期宽，就是这处。

### 4.3 底部导航 LiquidBottomTabs（**真机反馈轮新组件，全量验**）

本轮把底部"对话/模型/设置"重写为 Kyant0 式四层结构（滑动指示面板 +
隐形回显行 + 滑动指示胶囊），选中态从"材质厚薄区分"升级为"胶囊滑动跟随"。

1. **单击已选中页签**（手指落在高亮胶囊上）：8dp 内不消费，必须正常无反应/
   或保持选中（**这是"点了没反应"那口井的专项** —— 胶囊手势与页签 clickable 同点叠加）
2. **单击未选中页签**：胶囊从当前位置**滑过去**（不是瞬移），到达后吸附
3. **按住胶囊横向拖动**：胶囊跟手滑动、面板 4dp 拉伸、松手吸附最近页签并回调切换
4. **拖到首末端**：不溢出不卡死，面板拉伸回弹
5. **导航返回 / 程序化切页后**：胶囊自动滑回正确位置（外部 selectedIndex 回流）
6. **设置里关掉「背景模糊」**再看底部导航：退化为常驻底色 + accent 描边选中框，
   不空窗、选中信号仍可辨（描边约 0.5dp 视觉宽，若太细报回来，两边同步加宽）
7. **旋转 / 分屏**后拖动换页：跟手比例正常（tabWidth 已 State 化，旧闭包 bug 已修）
8. **低端机帧率**：拖动胶囊时看是否掉帧（胶囊开了色散 7 采样，面积小理论扛得住）

### 4.4 GlassSegmented 指示胶囊（CPU/GPU/NPU 那排，新结构）

分段控件重写为三层骨架（可见行 / 回显行 / 滑动胶囊），与底部导航同一套机制：

1. **单击已选中段**：8dp 分流，点击直达（不得"点了没反应"）
2. **单击未选中段**：胶囊滑过去、文字高亮切换
3. **按住胶囊横拖**：项间滑动过渡、松手吸附；item 文字被胶囊折射出"发光"效果
4. **回归**：各页的 Segmented（对话参数 本地/远程 + 思考模式、模型页 CPU/GPU/NPU、

5. **回归**：分段项**纯点击**仍触发（`dc89569` 删了旧按压手势层，按压反馈只剩

### 4.5 空对话页按钮排 + 模型卡卡内滚动（新功能）

1. **空对话页三个按钮**：导入本地模型 / 下载推荐模型 → 模型页；配置远程端点 → 端点页。

## 5. 对话页灌 30+ 条消息快速滚动（**验证 P1-3：色散开销**）

- **操作**：
  1. 进对话页，灌 **30 条以上**消息（本地模型来不及就用远程端点，重点是要够长）
  2. 确保其中**有几条带思考块**、**有几条带附件**（这两类气泡结构最重）
  3. 先清零统计，再**快速来回滚动**几轮：
     ```bash
     adb shell dumpsys gfxinfo com.rickeal.agent.debug reset
     # （在 App 里快速滚动 30+ 条气泡，来回几轮）
     adb shell dumpsys gfxinfo com.rickeal.agent.debug
     ```
  4. 看输出里的 `Janky frames` 占比与帧耗时分位数（50th / 90th / 95th / **99th**）
- **预期**：
  - 滚动**不卡顿**，气泡不出现白块 / 闪烁
  - 参考判据：60Hz 下一帧预算 16.7ms；99th 分位明显超过它就是开始掉帧，**超过 32ms 属于肉眼可感的卡顿**
  - 不同 Android 版本 `gfxinfo` 的输出格式会有差异，**以「Janky frames 占比」+ 主观是否卡顿两者一起判**
- **不合格时的排查指向**：
  - **"滚动掉帧"** → 先看色散是不是被打开了。大面积容器必须关：`GlassBubble` / `ThinkingBlock` / `AttachmentItem`
    都应显式 `dispersion = false`，且 `liquidGlass` / `LiquidGlassSurface` 的 `dispersion` **默认值必须是 `false`**。
    验收硬标准：`grep -rn "dispersion: Boolean = true"` 应**零命中**（commit `b63cca7` 修的就是这个）
  - **"只有带思考块 / 附件的气泡卡"** → 这两个是气泡内嵌套的容器，容易漏关
  - **"低端机卡但旗舰机不卡"** → 属预期差异。可先关「背景模糊」开关复测（关掉后玻璃只保留底色与描边，中低端机明显更流畅）

## 6. 按返回键（两段式）

- **操作**：按这个顺序点，每一步只按**一次**返回键

  2. 进设置页 → 按返回
  3. 进设置页的**某个子页**（如端点详情）→ 按返回
  4. 连续**快速按 5 次**返回
  5. 在三个页签间**来回切 10 次** → 按返回

  - 切页签 10 次后 → 按 2 次即退出（**不是 10 次**）
- **不合格时的排查指向**：

  - **"按返回在页签间倒着走"** → 返回键被导航层消费了

    有就说明 `startDestination` 与 composable 注册的 route **不同源**（前者必须是带参数的 PATTERN，不是裸 `chat`）
  - **"设置子页按返回先回了设置页"** → 两段式策略没覆盖子页
  - **根因与证据链**：见 [`docs/09-back-navigation.md`](09-back-navigation.md)，那边给到了 Navigation 2.8.9 的源码行号

## 8. TalkBack / 键盘（**验证 P1-2：无障碍**）

修复前开关"能念出'开关'但双击切不动"——那不是降级，是**完全不可用**。

  1. 打开 TalkBack，用**双击**激活一个开关（设置页那三个）

  3. 接外接键盘：Tab 到开关上按 **空格 / 回车**；Tab 到滑块上按 **左右方向键**、**Home / End**

## 9. 低端机 / API 31~32（无 AGSL）降级

本 App `minSdk = 31`。API 31~32 **没有 AGSL**，折射与色散跑不了，必须降级而不是崩。

- **操作**：在一台 **API 31 或 32** 的机器（或对应模拟器）上，把 §2 ~ §8 再走一遍
- **预期**：
  - **不崩溃**
  - **不出现黑块 / 花屏 / 玻璃整块消失**
  - 玻璃**退化为纯模糊**（背景仍能模糊，只是没有折射厚度带和色散）
  - 高光退化为**静态渐变**（不是动态方向性高光）——这是 API 限制的必然结果
- **不合格时的排查指向**：
  - **"崩了 / 黑块"** → AGSL 门控漏了。能力探测集中在 `LiquidGlassCapabilities`
    （`hasRuntimeShader` = API ≥ 33）。代码里**不应**直接写 `Build.VERSION.SDK_INT >= 33`，
    否则会与版本策略脱钩
  - **"效果与 API 33+ 一模一样"** → 反而可疑：说明门控没生效，低端机上硬跑了 AGSL
- **注意**：这一档下 logcat 出现 `LiquidGlass: lens 跳过折射：shape=...` 是**正常的**（见 §1），不要报

## 10. 不合格时怎么报（一页速查）

| 你看到的现象 | 直接查这里 | 验收硬标准（grep 一下就知道） |
|---|---|---|
| 开关点了不切换 | `GlassSwitch.kt` 的 `draggedX` / `touchSlopPx` | 不应出现 `dragAmount.x != 0f` |
| **按钮 / 页签点了没反应**（含底栏侧栏） | `InteractiveHighlight.kt` 的 `gestureModifier` | 必须按**累积**位移越过 `viewConfiguration.touchSlop` 才 `consume()` |
| 开关 TalkBack 双击切不动 | 外层 `toggleable` + `heightIn(min = tokens.minTouchTarget)` | 不应只有孤立的 `role = Role.Switch` |
| 滑块点不中 / 值不保存 | 48dp 外层 + `onValueChangeFinished` 落盘 | 手势不能挂在 6dp 轨道上 |
| **按在滑块上滑不动页面** | `DampedDragAnimation.kt` 的轴向锁定 | 纵向意图判定必须是 `abs(accumulatedY) > abs(accumulatedX) * VERTICAL_INTENT_TAN30(0.577)` 且 **break** 让位；阈值写成 45° 会在 30°~45° 留死区 |
| **模型页按在按钮/chip 上滑不动** | `InteractiveHighlight.kt` 的 `VERTICAL_INTENT_TAN30` break 分支（约 :203） | 同上：0.577 阈值 + break，不能只跳过 `consume()` |
| **滑块拖动抽动 / 不跟手 / 到不了首末端** | `GlassSlider.kt` 的 `onDrag` | 必须是 `dragAccumPx` 手势内累积 + `dragStartValue` 绝对映射；出现 `targetValue + delta` 增量基准即回归 |
| 气泡滚动掉帧 | 大面积容器的 `dispersion` | `dispersion: Boolean = true` 应零命中 |

## 11. 跨波次积压（Wave 33–38）

### 11.0 先读：这份清单的取证前提（Wave 39 新增）

Wave 33 起累计的验收项**从未被回收过**（≈32 条，零记录）。此前无法回收的**真实原因是取证通道是断的**：

| 事实 | 后果 |
|---|---|
| 6 组验收关键字原本**全是 `AgentLogStore.info/warn` 级** | 只在**内存 200 条环形缓冲**里（KDoc 明写「不落盘、杀进程即清空」） |
| 落盘的 `AgentLogFileStore` **只转发 ERROR** | 关键字**不在**落盘文件里 |
| 全仓原本**不写 `android.util.Log`**（这条链路上） | **`adb logcat` 抓不到任何一条关键字** |
| 诊断页原本**无复制/导出** | 用户无法把日志带出来 |

⇒ **Wave 39 已修**（本清单因此才可执行）：

- **新增 logcat 出口**：TAG = **`LiquidAgentDiag`**，**全级别**（INFO/WARN/ERROR）转发，行格式 `[LEVEL] message`（`message` 已过脱敏 + 400 字符截断）。
  - **抓取命令**：`adb logcat -s LiquidAgentDiag:V`（或 `adb logcat -s LiquidAgentDiag:V > d.log` 落文件）
  - release 包**没有**这条输出（`Log.d` 由 R8 按 `proguard-rules.pro` 剥离）⇒ **取证必须用 debug 包**，或用带 logcat 的 Release 复现构建。
  - ⚠️ **分叉判据**：debug 复现 → 正常取证；debug 不复现而 release 复现 ⇒ 判定为 **R8 相关新问题**（`Log.d` 被剥离只是表象，混淆/内联/资源收缩都可能改变行为）——logcat 通道失效，需**专门取证设计**（release 构建临时加 `-keep` 落点复现、或对照 `mapping.txt` 反混淆崩溃栈），**不得**用 debug 包的日志反推 release 行为。
- **诊断页新增「复制全部」按钮**（设置 → 诊断）：把「上次崩溃前的记录（磁盘）」+「本次运行（内存）」两区**当前可见**内容拼成纯文本进剪贴板，并有 Toast 反馈（含条数）。
- **落盘文件**（`last_errors.log`）**只收 ERROR**，用途是崩溃幸存 —— 不要指望在里面找到 INFO/WARN 关键字。
- ⚠️ **6 组关键字里有 4 组是 WARN 级**，抓取时**不要只过滤 INFO**（下表已逐条标注级别）。

> **本清单的性质**：条目来自各波 handoff 的验收段（已逐条注明来源波次），**尚未真机执行**。
> 与真机不符时**以真机为准**，并当作 bug 报回来。
