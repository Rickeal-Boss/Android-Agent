# 真机验收清单（用户视角，按操作路径排序）

> **这份清单是给谁用的**：拿到 debug 包、准备逐条验收的人。
>
> **为什么必须有这份清单**：CI 只跑 `assembleDebug`——它只能证明代码**能编译**，
> 一行运行时行为都验不到。而本轮改的缺陷几乎全是**静默**的：不崩、不报错，只是结果错。
> 这些只有真机能验。
>
> **怎么读**：按 §2 → §9 的顺序往下做，这就是你拿到包后最自然的动线，
> **不要按代码模块跳着做**。每一条都有三样东西：
> - **操作**：具体到"点哪里、怎么点"，不写"验证某某功能"这种没法执行的话
> - **预期**：应该看到什么。**这是判定通过的唯一标准**，不是"看起来没崩就算过"
> - **不合格时**：往哪儿排查、该报给谁、报的时候要带上什么
>
> **配套**：
> - [`docs/09-back-navigation.md`](09-back-navigation.md) —— 返回键的根因与证据链（§7 只给结论）
> - [`docs/05-device-verification.md`](05-device-verification.md)、[`docs/06-device-verification-checklist.md`](06-device-verification-checklist.md)
>   —— 上一轮**引擎/模型侧**的验证项。本文件只管**玻璃 UI**，两边不重叠，别混着看
>
> **诚实标注**：本文所有"预期"来自源码与修复 commit，**不是**已完成的真机实测。
> 真机结果与本清单不符时，**以真机为准**，并把它当作一个 bug 报回来。

## 1. 本版本的已知取舍（**不要当 bug 报**）

这一节请先看。下面是**有意为之**的设计决定，报上来会被退回，但会浪费你一轮沟通。

| 现象 | 为什么是有意的 | 出处 |
|---|---|---|
| **顶栏不是胶囊**，是整条全宽 | 全宽顶栏做成胶囊会把标题挤进两端圆角里，标题会被裁 | `GlassTopBar.kt:47`（`fillMaxWidth`，无 `capsule`） |
| **输入框不是胶囊**，且观感与其他玻璃件不同 | 输入框**刻意不走** `LiquidGlassSurface` 门面——门面的按压反馈只由 `onClick` 驱动，而输入框没有 onClick，它的"变实"必须走**聚焦**这条 | `GlassTextField.kt:62-65` |
| **滑块 / 开关的 thumb，静止时是白色实心**，按下才变透明露出折射 | 对齐 Kyant0 原实现。**不是**"白色没做透明"的 bug | `GlassSlider.kt:387`、`GlassSwitch.kt:259` |
| **卡片 / 对话框 / 对话气泡没有色散**（边缘没有彩虹色带） | 色散要 7 次采样、约 7 倍开销。气泡是全 App 最长的列表，一屏十几条，开着必掉帧。**性能取舍，不是效果缺失** | commit `b63cca7` |
| **色散只出现在小控件上**（滑块 / 开关的 thumb） | 面积小才扛得住 7 倍开销，这是本轮刻意保留的 | `GlassSlider.kt:353`、`GlassSwitch.kt:188` |
| logcat 里出现 `LiquidGlass: lens 跳过折射：shape=... 不是 ...` | **正常且无害**。传非 `Capsule` 形状本身合法，只是拿不到折射优化。级别是 `Log.d`，release 包会被 R8 整条删掉 | `Lens.kt:126-131` |

> 另有一条**本轮已变更**、容易误判的：
> **底栏页签项是跟手的**（按住会跟着手指位移、沿拖动方向拉长，松手回弹）。
> 早期版本不跟手，后来在 NavBar/NavRail 改造里补上了。
> 所以 §7 的"拖动跟手"**是要求实现的**，不是取舍。若你手上的包不跟手，那是 bug，请报。

## 2. 装包第一眼：整体观感

不点任何东西，先把 App 打开看 5 秒。这一步判断的是"玻璃是不是玻璃"。

### 2.1 胶囊轮廓
- **操作**：进设置页，看那些按钮 / Chip / 分段项的两端
- **预期**：两端是**正半圆**，不是被压扁的跑道形。上下边缘平直，只在两端收圆
- **不合格时**：报"胶囊被压扁"，附截图。指向 `liquid/shapes` 的 `Capsule` 与 `cornerRadius` 的取值关系

### 2.2 折射与色散是否可见
- **操作**：找一个**小控件**（设置页的开关、滑块），看它的 thumb 边缘
- **预期**：
  - 能看到**折射**——边缘有一圈"厚度渐变带"，像一块有厚度的玻璃而不是一张半透明贴纸
  - 小控件的 thumb 上能看到轻微**色散**（边缘彩虹色）
  - **大面积**的卡片 / 气泡**没有**色散（见 §1，这是有意的）
- **不合格时**：
  - 完全没有折射 → 可能是 API 31~32 降级（见 §9），或背景模糊开关被关掉了
  - 小控件也没有色散 → 检查 `GlassSlider.kt:353` / `GlassSwitch.kt:188` 的 `chromaticAberration = true` 是否被改成 `false`

### 2.3 壁纸光斑
- **操作**：换一张**有明显明暗变化**的壁纸，回 App 看玻璃后面的背景
- **预期**：玻璃后面能看到壁纸的内容与光斑，且被"提鲜"过（饱和度略高），不是一片死板的灰
- **不合格时**：背景一片纯色 / 玻璃像素级透出壁纸（等于玻璃消失）→ 指向 `LocalBackdrop` 与 `enableBackdropBlur` 的联动

## 3. 点三个开关（**验证 P1-1：点了要切换**）

这是本轮**最重要**的一条。修复前"点开关只是抖一下弹回去，状态不变"——真机第一眼就会踩。

- **操作**：设置页 → 外观分区，依次点这三个开关：**背景模糊**、**噪点微纹理**、**减弱动效**
  1. 每个开关**连点 10 次**，每次都要切换
  2. **手指故意带 1~3px 的横向位移**再松手（真机上没有绝对静止的点击，这一条最能暴露回归）
  3. 按住 thumb **拖过一半**再松手，看是否吸附到那一侧
- **预期**：
  - 连点 10 次 → **10 次都切换**，一次都不能"抖一下弹回原状态"
  - 带 1~3px 位移 → **仍然切换**
  - 拖过半松手 → 吸附到手指那一侧，不会弹回
- **不合格时的排查指向**：
  - **"点了不切换"** → 判定拖动的阈值回归了。查 `GlassSwitch.kt` 里的 `draggedX` 累积与 `touchSlopPx`（应为 `8.dp.toPx()`）。
    验收硬标准：该文件里**不应出现** `dragAmount.x != 0f`（这是修复前的写法，只要横向位移非零——**亚像素也算**——就误判成拖动）
  - **"一次点击回调了两次"** → 纯点击的提交被重复走了。正确做法是纯点击交给外层 `toggleable` 统一提交，
    拖动的提交在 `onDragStopped` 里，两者互斥
  - **"手指带位移就不切换"** → 阈值被调得过大，或又退化成"位移非零即拖动"
  - **"轻点有反应，但位移一小点就完全没反应"** → 拖动手势**一动就消费事件**了，会把外层
    `toggleable` 的点击一起取消。正确做法是给手势传 `consumeSlopPx = touchSlopPx`——
    **只有真拖动才消费**，抖动 1px 时点击原样交给 `toggleable`

## 3.5 逐个点所有玻璃控件（**验证 P0：点了必须有反应**）

**本轮最容易漏、也最致命的一条。** 修复前"所有玻璃按钮 / 分段项 / 页签点了都没反应"——
CI 和静态审查都发现不了，只有真机能复现。

> **为什么 §3 测了开关还不够**：开关走的是 `DampedDragAnimation`（`GlassSlider` 同），
> 而下面这批走的是 **`InteractiveHighlight.gestureModifier`** —— 是**另一条代码分支**。
> 只修一条的话，**另一批会全挂而开关好好的**。两条都要验到。

- **操作**：依次点击下面这些，**每个都点 5 次**，且**手指故意带 1~3px 抖动**再松手
  （真机没有绝对静止的点击，这一条最能暴露回归）：
  1. 设置页里的**按钮**与 **Chip**
  2. 设置页里的**分段项**（每个分段都点一遍）
  3. 悬浮按钮 **Fab**（若有）
  4. 设置页里的**每一行**（可点击的设置行）
  5. **顶栏的图标按钮**（返回箭头等）
  6. **底栏的三个页签**（聊天 / 模型 / 设置）—— 点了要真的切页
  7. 宽屏 / 横屏下的**侧栏页签**
- **预期**（两条必须**同时**成立，只有一半就是改错了方向）：
  1. 每一次点击都要**有响应**——状态变化 / 页面切换 / 回调触发
  2. **跟手形变照常出现**——按住会跟着手指动、松手回弹

  > 第 2 条不是顺带提的：这个修复只改了"什么时候把事件标记为已消费"，**没动**跟手位移
  > 的计算。所以如果点击修好了但跟手没了（或反过来），说明改的方向不对——
  > 比如为了修点击直接把 `consume()` 删掉，那父级滚动就会来抢手势。
- **不合格时的排查指向**：
  - **"点了完全没反应，但跟手形变还在动"** → 手势**一动就消费事件**，把外层 `clickable`
    的按压取消了。正确做法是**累积**位移越过 touch slop 才 `consume()`（不是按单帧 delta 判）——
    见 `InteractiveHighlight.kt` 的 `gestureModifier`
  - **"只有开关能点，按钮 / 页签不行"** → 只修了 `DampedDragAnimation` 那条分支，
    漏了 `InteractiveHighlight` 这条。见上面那段说明
  - **"轻点有反应，稍微动一点就没反应"** → slop 没生效，或阈值被写死成 0
  - **"点击好了但页面一划就跟着动 / 滚不动了"** → 修过头了：`consume()` 被删干净，
    父级滚动抢不到手势

## 4. 设置页滑块（玻璃质感强度）

- **操作**：设置页 → 外观 → 「玻璃质感强度」滑块（范围 0.5~1.5）
  1. **拖动**：按住 thumb 左右拖，看数值是否连续变化
  2. **松手落盘**：拖到一个明显的值（比如 1.30），**退出设置页再进来**，看是否还在
  3. **点轨道跳转**：点轨道中间某个位置，看 thumb 是否跳过去
  4. **行高是否够按**：用拇指点，看是否容易点偏
- **预期**：
  - 拖动时数值**连续变化**（不是一跳一跳）
  - 退出重进后**值仍在**（拖动期间只改内存，松手才落盘一次——这是刻意的，避免每帧写盘掉帧）
  - 点轨道中间 → thumb 跳到该位置
  - 轨道虽然只有 6dp 高，但**上下有 48dp 的触摸区**，不该点偏
- **不合格时的排查指向**：
  - **"值没保存"** → 落盘时机不对。检查 `onValueChange`（只 preview，改内存）与 `onValueChangeFinished`（commit，写盘）是否分开了
  - **"拖动时明显掉帧"** → 松手前的每帧写盘回来了。该项值变化会触发全 App 重组 + 每个玻璃节点重画，再叠加写盘必然卡
  - **"点轨道中间没反应 / 很难点中"** → 触摸目标没生效。正确做法是 48dp 的触摸区挂在**外层**，手势也挂外层；
    若手势挂在 6dp 的轨道本体上，上下留白就是"看得见点不到"

## 5. 对话页灌 30+ 条消息快速滚动（**验证 P1-3：色散开销**）

- **操作**：
  1. 进对话页，灌 **30 条以上**消息（本地模型来不及就用远程端点，重点是要够长）
  2. 确保其中**有几条带思考块**、**有几条带附件**（这两类气泡结构最重）
  3. 先清零统计，再**快速来回滚动**几轮：
     ```bash
     adb shell dumpsys gfxinfo com.rickeal.agent.debug reset
     # （在 App 里快速滚动 30+ 条气泡，来回几轮）
     adb shell dumpsys gfxinfo com.rickeal.agent.debug
     ```
  4. 看输出里的 `Janky frames` 占比与帧耗时分位数（50th / 90th / 95th / **99th**）
- **预期**：
  - 滚动**不卡顿**，气泡不出现白块 / 闪烁
  - 参考判据：60Hz 下一帧预算 16.7ms；99th 分位明显超过它就是开始掉帧，**超过 32ms 属于肉眼可感的卡顿**
  - 不同 Android 版本 `gfxinfo` 的输出格式会有差异，**以「Janky frames 占比」+ 主观是否卡顿两者一起判**
- **不合格时的排查指向**：
  - **"滚动掉帧"** → 先看色散是不是被打开了。大面积容器必须关：`GlassBubble` / `ThinkingBlock` / `AttachmentItem`
    都应显式 `dispersion = false`，且 `liquidGlass` / `LiquidGlassSurface` 的 `dispersion` **默认值必须是 `false`**。
    验收硬标准：`grep -rn "dispersion: Boolean = true"` 应**零命中**（commit `b63cca7` 修的就是这个）
  - **"只有带思考块 / 附件的气泡卡"** → 这两个是气泡内嵌套的容器，容易漏关
  - **"低端机卡但旗舰机不卡"** → 属预期差异。可先关「背景模糊」开关复测（关掉后玻璃只保留底色与描边，中低端机明显更流畅）

## 6. 按返回键（两段式）

- **操作**：按这个顺序点，每一步只按**一次**返回键
  1. 在对话页 → 按返回
  2. 进设置页 → 按返回
  3. 进设置页的**某个子页**（如端点详情）→ 按返回
  4. 连续**快速按 5 次**返回
  5. 在三个页签间**来回切 10 次** → 按返回
- **预期**（两段式：第一次一律先回对话页，再一次退出）：
  - 对话页 → **直接退出**
  - 设置页 → **回对话页**；再按一次退出
  - 设置子页 → **直接回对话页**（**不是**先回设置页）；再按一次退出
  - 连按 5 次 → 不 ANR、不卡死
  - 切页签 10 次后 → 按 2 次即退出（**不是 10 次**）
- **不合格时的排查指向**：
  - **"按 N+ 次才退出"（切了 N 次页签）** → 回退栈随切页签增长了，正常应恒为 1
  - **"按返回在页签间倒着走"** → 返回键被导航层消费了
  - **"按返回毫无反应"** → 这条最阴。先看 logcat 有没有
    `Ignoring popBackStack to destination ... as it was not found on the current back stack`——
    有就说明 `startDestination` 与 composable 注册的 route **不同源**（前者必须是带参数的 PATTERN，不是裸 `chat`）
  - **"设置子页按返回先回了设置页"** → 两段式策略没覆盖子页
  - **根因与证据链**：见 [`docs/09-back-navigation.md`](09-back-navigation.md)，那边给到了 Navigation 2.8.9 的源码行号

## 7. 底栏 / 顶栏：按住拖动看是否跟手

- **操作**：
  1. 按住底栏的**某个页签项**（不是整个底栏），**横向拖动**约 1~2 厘米，手指不离开屏幕
  2. 拖动时看这个页签项本身
  3. 松手
- **预期**：
  - 该页签项的玻璃**跟着手指位移**（位移是 `tanh` 阻尼的：拖多远都不会飞出去）
  - 拖动方向上被**拉长**、垂直方向被**压扁**（各向异性）——这是"液态"最直观的信号
  - 松手**回弹**到原位
  - **只有被按住的那一项**动，其他页签项不动
- **不合格时的排查指向**：
  - **"完全不跟手"** → 跟手形变没接上。查 `LiquidAgentApp.kt` 里页签项的
    `layerBlock = pressLayerBlock(interactiveHighlight, maxScale = 16.dp)` 是否还在
  - **"所有页签项一起动"** → `InteractiveHighlight` 被**共用**了。每个页签项必须**各自持有**一个实例
  - **"拖一下页面就翻页 / 触发了点击"** → 拖动与点击抢事件了

## 8. TalkBack / 键盘（**验证 P1-2：无障碍**）

修复前开关"能念出'开关'但双击切不动"——那不是降级，是**完全不可用**。

- **操作**：
  1. 打开 TalkBack，用**双击**激活一个开关（设置页那三个）
  2. 焦点移到滑块上，用 TalkBack 的**增加 / 减少**操作调它
  3. 接外接键盘：Tab 到开关上按 **空格 / 回车**；Tab 到滑块上按 **左右方向键**、**Home / End**
- **预期**：
  - 开关：TalkBack 念出"开关，开 / 关"，**双击能真正切换**
  - 滑块：能播报**当前值**，且用无障碍操作能改变它
  - 键盘：开关能被空格 / 回车切换；滑块能用方向键按步长增减，Home / End 到两端
  - **禁用态的开关**：TalkBack 应念出"已停用"，且操作无效
- **不合格时的排查指向**：
  - **"能念出开关但双击切不动"** → 缺 `toggleable`。正确做法是整块外层用
    `Modifier.toggleable(value, role = Role.Switch, ...)`；只有一个孤立的
    `semantics { role = Role.Switch }` 是不够的——那是**能念不能操作**
  - **"role 挂在 thumb 上"** → 语义节点放错了位置，应该挂在**整个开关**上
  - **"滑块播不出当前值 / 调不动"** → 缺 `ProgressBarRangeInfo` 与 `setProgress`
    （Compose 的 `Role` 里没有 Slider，foundation 的 `sliderSemantics` 是 internal，只能手写）
  - **"键盘完全没反应"** → 缺 `.focusable()` 与 `onKeyEvent`
  - **"48dp 触摸区白给了"** → 触摸目标挂在了 thumb 而不是外层，见 §4 同一条

## 9. 低端机 / API 31~32（无 AGSL）降级

本 App `minSdk = 31`。API 31~32 **没有 AGSL**，折射与色散跑不了，必须降级而不是崩。

- **操作**：在一台 **API 31 或 32** 的机器（或对应模拟器）上，把 §2 ~ §8 再走一遍
- **预期**：
  - **不崩溃**
  - **不出现黑块 / 花屏 / 玻璃整块消失**
  - 玻璃**退化为纯模糊**（背景仍能模糊，只是没有折射厚度带和色散）
  - 高光退化为**静态渐变**（不是动态方向性高光）——这是 API 限制的必然结果
- **不合格时的排查指向**：
  - **"崩了 / 黑块"** → AGSL 门控漏了。能力探测集中在 `LiquidGlassCapabilities`
    （`hasRuntimeShader` = API ≥ 33）。代码里**不应**直接写 `Build.VERSION.SDK_INT >= 33`，
    否则会与版本策略脱钩
  - **"效果与 API 33+ 一模一样"** → 反而可疑：说明门控没生效，低端机上硬跑了 AGSL
- **注意**：这一档下 logcat 出现 `LiquidGlass: lens 跳过折射：shape=...` 是**正常的**（见 §1），不要报

## 10. 不合格时怎么报（一页速查）

| 你看到的现象 | 直接查这里 | 验收硬标准（grep 一下就知道） |
|---|---|---|
| 开关点了不切换 | `GlassSwitch.kt` 的 `draggedX` / `touchSlopPx` | 不应出现 `dragAmount.x != 0f` |
| **按钮 / 页签点了没反应**（含底栏侧栏） | `InteractiveHighlight.kt` 的 `gestureModifier` | 必须按**累积**位移越过 `viewConfiguration.touchSlop` 才 `consume()` |
| 开关 TalkBack 双击切不动 | 外层 `toggleable` + `heightIn(min = tokens.minTouchTarget)` | 不应只有孤立的 `role = Role.Switch` |
| 滑块点不中 / 值不保存 | 48dp 外层 + `onValueChangeFinished` 落盘 | 手势不能挂在 6dp 轨道上 |
| 气泡滚动掉帧 | 大面积容器的 `dispersion` | `dispersion: Boolean = true` 应零命中 |
| 返回键按 N+ 次 / 毫无反应 | [`docs/09`](09-back-navigation.md) | `startDestination` 与 route 是否同源 |
| 底栏拖动不跟手 | `LiquidAgentApp.kt` 页签项的 `pressLayerBlock` | 每个页签项各自持有 `InteractiveHighlight` |
| 低端机崩 / 黑块 | `LiquidGlassCapabilities` 的 AGSL 门控 | 不应硬写 `SDK_INT >= 33` |
| 顶栏 / 输入框不是胶囊 | **不用报**，见 §1 | 有意为之 |
| thumb 静止是白色实心 | **不用报**，见 §1 | 对齐 Kyant0 |
| 气泡没有色散 | **不用报**，见 §1 | 性能取舍 |
| logcat 有 `lens 跳过折射` | **不用报**，见 §1 | `Log.d`，release 被 R8 删 |

**报的时候请带上**：机型、Android 版本、`adb shell dumpsys gfxinfo` 输出（如果是卡顿问题）、
截图或录屏（如果是观感问题）、以及 logcat 里 `LiquidGlass` tag 的相关行。
