# W89 交接 — UI 修复波（2026-10-27）

分支 `core-fix`，波前 tip `dc930ca`（W88 收尾）。输入 = 用户点名的三项 UI 缺陷
（沙箱工作区模糊中途突变 / 推理参数覆盖层缓慢退出掉帧 / 横屏页签挪到顶部）
＋ 两份外审报告的收尾期剩余清单。

## 一、波次定性

W88 把「看得见的交互」收了一轮，本波是**同一批交互的残余**：两处是**根因级**缺陷
（一个双进度源打架、一个每帧重画整屏），一处是**形态变更**（横屏一级导航从左侧竖栏
改为顶部横条）。三项都先做真机取证再改，改完用同一套脚本复测同一组数字。

| 需求 | 真缺陷（回源核验后） | 处置 |
|---|---|---|
| 沙箱工作区模糊「中途强度突变」 | 工作区面板的模糊有**两个进度源**：锚点位移（跟手）与 `LocalOverlayBlurState` 的 SHELL 弹簧，`MainShell` 里取 `max`。SHELL 弹簧只在拖过**两锚点中点**后才释放 ⇒ 前半程 `max` 恒为 1（面板滑走、背景纹丝不动），过中点后弹簧从 1 衰减（与手指位置无关）⇒ 一帧内由"全糊"变"大半清晰" | W89-01 |
| 推理参数覆盖层缓慢退出掉帧 | `overlayBackdropBlur` 在 `p<1` 的**整个区间**里既 `drawContent()` 又叠缩略图 ⇒ 每一帧重画整棵子树（壁纸 layerBackdrop 全屏离屏录制 + 每个玻璃节点的 backdrop 采样）。真机 `gfxinfo`：10s 慢拖 **764 帧 / 741 卡顿（96.99%）/ 50th 36ms**；关掉「背景模糊」总闸对照 **950 / 16（1.68%）/ 19ms** ⇒ 每帧多付 ~17ms | W89-02 |
| 横屏一级导航挪到顶部 | `useTwoPane` 只看宽度 ⇒ 横屏手机走 `GlassNavRail`（左侧竖栏），正文横向被切掉 88dp + 两侧内边距，整页看起来"不是全屏" | W89-03 |

## 二、真机取证（先量再改）

设备 OPPO PDRM00（`13309cc8` / Android 13 / SDK 33，1080×2400 @480dpi）。
设备**没有 `screenrecord`**（ColorOS 移除），所以用「长时慢拖 + 并发截图」替代：
`input swipe` 一条 10~12s 的连续手势，主线程每 ~0.4s 抓一张 `screencap`，
每张截图自带**被测控件的几何位置**（面板左缘 / sheet 顶边）⇒ 进度 `p` 与
"清晰度"两个量都在同一帧里，不依赖任何时序假设。

度量取两个互相独立的探针：
- **清晰度** = 固定背景带的 Laplacian 方差（高频能量，模糊越大越小）；
- **压暗** = 同一背景带的平均亮度（scrim alpha 严格线性于 p，是 `p` 的**线性**探针）。

### 2.1 工作区面板「关闭拖拽」——修复前（W88 代码）

| 面板左缘 | 位移进度 p | 清晰度 |
|---:|---:|---:|
| 194→613（拖了 47% 行程） | 1.00→0.53 | 0.59→0.42（**一直全糊**） |
| **639（刚过两锚点中点）** | 0.50 | **0.42 → 143.47（一帧内变清晰）** |
| 870 | 0.24 | 293 |

⇒ 「中途突变」的机理被钉死在中点上：`shellBlurProgress` 的释放时机 = `currentValue`
翻档，而它翻档的时机 = 拖过两锚点中点。

### 2.2 同一手势——修复后

| 面板左缘 | 位移进度 p | 压暗（线性探针） |
|---:|---:|---:|
| 194（全开） | 1.00 | 221.7 |
| 389 | 0.78 | 226.1 |
| 629 | 0.51 | 229.1 |
| 882 | 0.22 | 232.3 |
| 1039 | 0.045 | 234.3 |
| 1079（全关） | 0.00 | 234.8 |

⇒ **单调、线性、无台阶**。中点处（左缘 629~659）清晰度 0.71~0.75，与相邻样本同档
（修复前同位置是 143）—— 突变消失。

## 三、辩证核验（3 条处方被降级/改写）

| # | 处方 | 回源核验 | 处置 |
|---|---|---|---|
| V1 | 「把缩略图 `alpha = p` 改成 `alpha = 1`，p≥某阈值后跳过内容绘制」（外审给的形态） | ⚠️ 阈值不能拍脑袋定：`alpha=1` 时背景是**降采样后再放大**的图，本身就有 `0.5/scale` 的软化量（本机 ≈0.7dp）。阈值取小了会在切换点"啪"一下变软，取大了又回到双重曝光 | 阈值**由半径与缩放推导**（`coverThresholdOf = (1/scale)/radiusPx`，夹在 0.03~0.35）：物理含义是"交叉淡入两端视觉等价"的那一点。半径调大自动更早覆盖，无需按档位手调 |
| V2 | 「工作区面板注册 SHELL 是为了让页签条也糊，去掉会漏一条"清晰页签浮在糊背景上"」 | ⛔ 该分支（`navBarBlurProgress` / `anyActive`）**已在 UI-1019 Batch 2 撤除**：`anyActive` 全仓**零消费方**（grep 确认）⇒ 这条登记只留下"第二个进度源"的副作用 | 直接删除登记（不是"再补一条 max"）；KDoc 里写清"为什么不能加回来" |
| V3 | 「横屏把 Rail 压窄/隐藏品牌字就够了」（W88 的做法） | ⚠️ 真机复验：竖栏本身让正文横向变窄，用户要的是"页签在上、正文吃满横向" | 新增 `TabBarPlacement` 三分支（Bottom/Rail/Top）纯函数；横屏手机走 Top。W88 的 Rail 压缩**保留**（平板仍走 Rail） |

## 四、落地清单

### 4.1 W89-01 工作区模糊（`WorkspaceOverlay.kt`）

- 删掉 `LocalOverlayBlurState` 的 SHELL 登记（含 `DisposableEffect` / `blurToken` /
  两个 import），模糊**只由 `workspaceBlurProgress`（锚点位移）驱动**。
- KDoc 换成真机数据表 + 机理说明，并写明「不要再加回来」。
- `MainShell` 的 `max(drawer, max(shell, workspace))` **不动**：抽屉与对话框仍走各自通道，
  工作区面板只是不再有第二条。

### 4.2 W89-02 模糊管线（`OverlayBackdropBlur.kt`）

- 新增 `coverThresholdOf(scale, radiusPx)` + `thumbnailCoverAlpha(p, coverFrom)`（均为
  `internal` 纯函数，6 例 JVM 单测）。
- draw block：`p ≥ coverFrom` 时**不再 `drawContent()`**，只画"256px 图层高斯 + 放大铺回"；
  `p < coverFrom` 用 smoothstep 淡入（两端视觉等价 ⇒ 切换点不可辨）。
- 顺带修掉双重曝光（旧实现 `alpha = p` 时是"50% 清晰 + 50% 模糊"的幽灵图）。

### 4.3 W89-03 横屏顶部页签（`WindowSizeClass.kt` / `GlassScaffold.kt` / `LiquidAgentApp.kt`）

- `TabBarPlacement { Bottom, Rail, Top }` + `WindowSizeClass.tabBarPlacement()` 纯函数
  （3 例单测：竖屏手机 Bottom / 横屏手机 Top / 平板 Rail，含 480dp 断点两侧）。
- `LocalTopBarOverlay`（新，`core-design`）：`GlassScaffold` 把整列下移该高度。
  **与底部条的消费方式刻意不同** —— 底部条是"内容从玻璃底下穿过"（只加滚动内边距），
  顶部条直接让位（横屏高度本就紧张，内容钻到条下面会被永久遮住一截）。
- `MainShell`：`tabPlacement` 一处判定，替换原先四处手写的 `useTwoPane && !isLandscapePhone`
  （W88 靠"三处逐字同源"维持的一致性，现在由纯函数保证）。
- 顶部条高度 **72dp**（条高 64 不动 + 外层内边距 10→4）：横屏可用高 344dp，
  84dp 会把空态挤掉半屏（真机实测）。
- `recordContent` 条件由 `!useTwoPane` 改为 `tabPlacement != Rail`：顶部条同样是悬浮玻璃条，
  需要 NavHost 录制层做背景源。

## 七、本波新坑与教训

1. 🔴 **"取 max" 不是"取更安全的那条"**：两条时间线取 max 时，只要其中一条**不跟手**，
   它就会在另一条之上形成**平台 + 突降**。判据不是"两条都指向同一个语义"，而是
   **"两条都在同一帧里由同一个输入驱动"**。W88 在参数面板上已经立过这条纪律
   （位移/压暗/模糊同源），本波只是发现工作区面板没照做。
2. 🔴 **"画了但看不见"的每帧成本照样要付**：`p<1` 时叠一层半透明缩略图，视觉上"差不多"，
   但 `drawContent()` 的代价是整棵子树重画（含全屏离屏录制）—— 真机 17ms/帧。
   **性能结论必须用 `gfxinfo` 数字说话，不能靠"看起来还行"**。
3. 🔴 **交叉淡入的两端不等价时，切换点一定看得见**：`alpha` 从 p 改到 1 不是纯粹的开关，
   必须把"缩略图自身的软化量"折进阈值（`coverThresholdOf` 的推导），否则只是把
   "双重曝光"换成"啪一下变软"。
4. **顶部条不是免费的**：横屏 344dp 里 72dp 是 21%。用户要"视觉全屏"得到的是**横向**，
   代价在**纵向** —— 空态必须再降一档（只留按钮）。这类"形态换预算"的改动要在
   真机上量到具体 dp，不能只按设计稿推算。
5. **`input swipe` 是可靠的"慢动作"工具**：设备没有 `screenrecord` 时，一条 10~12s 的
   swipe + 并发 `screencap`，比视频解码更省事，且每张图自带几何位置（不依赖时序假设）。
