## 一、真实压力面：**方法级**，不是文件级

| 维度 | 载体 | 守卫 | 当前 / 阈值 | 余量 | 是否真压力 |
|---|---|---|---|---|---|
| **方法级** | `executeBodyUnchecked`（`AgentRunner.kt:563`，下一个类内方法起于 `:1103` ⇒ 540 行） | **#12**（≤ 550） | **540 / 550** | **10** | ✅ **真压力**（JVM 单方法 64KB 上限，Wave 27 曾真实炸过 `Method too large`） |
| 文件级 | `AgentRunner.kt`（`wc -l` = 2802） | #31（≤ 2900） | **2802 / 2900** | 98 | ❌ 不是真压力（约 3.4% 余量，够用） |

> **一句话**：能「救」的是**方法体积**（#12），不是文件体积（#31）。把方法体里的大块**外提为类内/顶层函数**，方法行数才会降；单纯把**已在方法外**的函数挪到别的文件，只动文件行数。

## 二、🔴 关键纠正：被列为首刀的三个候选**层级错了**

W60 交接 / 第七审 §3.3 列出的三个「首刀」候选，**全部已在 `executeBodyUnchecked`（`:563–1102`）之外**：

| 候选函数 | 定义位置 | 是否在 `executeBodyUnchecked` 内 | 外提的作用 |
|---|---|---|---|
| `buildSystemSections` | `AgentRunner.kt:2569` | ❌ 已在方法外（类内 private） | 只减**文件**行数（#31），**不减方法行数**（#12） |
| `toolCallSignature` | `AgentRunner.kt:2788` | ❌ 已在方法外 | 同上 |
| `canonicalizeJson` | `AgentRunner.kt:2796` | ❌ 已在方法外 | 同上 |

⇒ **外提这三个候选对本波的真压力（#12 余 10）零帮助**。第七审 §3.3「把余量从 10 拉回几十行」的表述**混淆了文件级与方法级**。
（`buildSystemSections` / `toolCallSignature` / `canonicalizeJson` 各自「可否文件级纯函数化」的评估：三者均为**纯计算 / 无实例状态**，可外提为顶层 `internal fun` 并补 JVM 单测 —— 但那是**可读性 / 可测性**收益，**不是** #12 收益。）

## 三、真正能减 #12 的接缝（须在 `:563–1102` **内**外提）

按「收益 × 风险」排序（行号实测）：

| # | 接缝（方法内区间） | 内容 | 性质 | 预估减行 | 风险 |
|---|---|---|---|---|---|
| ① | **工具装配簇** `:637–693` | `useNativeTools` / `allToolSpecs` / `disclosureActive` / `hiddenToolCatalog` / `availableTools` / `registeredToolNames` / `allToolNames` | **近纯计算**（只依赖 `config` / `request` / `toolRegistry` / `capabilities`，无 emit、无实例状态） | **≈ 55** | **零行为风险**（须**保持求值顺序**：`useNativeTools` 先于 `allToolSpecs`，`disclosureActive` 依赖 `allToolSpecs`） |
| ② | **引擎加载 + 重试簇** `:596–629` | `try { engine.load } catch { rebuildEngine → 再失败则 error+emit+**早退** }` | 含**早退 `return`（`:621`）** ⇒ 外提须返回 **sealed 结果**（`Loaded` / `Aborted`）由调用点分派 | ≈ 30 | **中等**（控制流改写，需覆盖「重建成功 / 重建失败 / 取消」三态） |
| ③ | **系统提示 / 回显语料簇** `:695–739` | `working` / `systemText`（`:705`）/ `echoCorpus`（`:718`）/ 系统消息装配 / history 去重拼接 | **部分可外提**（`systemText` / `echoCorpus` 拼装为纯函数；`working` 的 `add` 顺序须逐字保持） | ≈ 20–35 | **低–中**（顺序敏感，`working` 与 journal 写入耦合） |

> **首刀建议**：先做 ①（近纯计算、零行为风险、减行最多），把 #12 从 540 拉回 **≈ 485**（余 ≈ 65）。若仍紧，再评估 ②（须引入 sealed 结果类型）。③ 留最后。
> **共同纪律**：外提函数优先做成**顶层 `internal fun` + `data class` 返回值**（如 ① 的 `data class ToolSetup`），保持**求值顺序**与**逐字节行为等价**，并补 JVM 纯逻辑单测（沿 W59 加载集群拆分 / W60 A4 外提的先例）。
