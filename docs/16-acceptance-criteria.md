## 一、为什么需要这份文件

本仓的规则现在**散在四处、互不索引**：

| 规则实际存放位置 | 数量级 | 问题 |
|---|---|---|
| `scripts/arch-guard.sh` 的注释头 | 61 条 | 判据可执行，但**只有写脚本的人读得到**；编号 `#N` 与「规则语义」没有稳定映射 |
| [`docs/15-backlog.md`](15-backlog.md) | 100+ 行 | 是**挂账**不是**规则**；一条规则可以在台账里被销账三次（不同波次各一条） |
| `docs/handoff-*.md` | 80+ 份 | 规则以「本波教训」形式散落，**没有任何跨波索引**；同一规则在 W24 / W52 / W84 各写一遍 |
| `README.md` 特性表 / 挂账台账 | 2 节 | 面向用户的能力声明与面向工程的纪律混在一起 |

**后果不是「不好看」，是三条具体的失败**：

1. **覆盖面不可数** —— 「本仓到底有多少条机械规则？」的答案是「跑一下 `arch-guard.sh` 看它打印什么」。
   而 `arch-guard.sh` 的编号到 `#62`，实际 `check` 调用 **61** 次（`#11` / `#53` 是空号 / 元 case）
   ⇒ **连「有多少条」都需要考古**。
2. **规则与判据会漂** —— 文档说「X 禁止」，脚本实际查的是「Y 禁止」，两者都不报错。
   W84 的 `oem/` 拆分脱闸就是这个形态：**规则写在注释里、判据没覆盖新文件**，
   于是「拆分把代码移出了守卫视野」——同一形态在 W52 / W64 / W83 已复发**三次**。
3. **新人 / 新 agent 无法自证合规** —— 没有单一事实源 ⇒ 只能「跑一下看红不红」，
   而**跑绿不等于合规**（判据可能没覆盖到你改的那块，见第 2 条）。

**目标形态**（借鉴两个工业级参考仓的「规则单一事实源 + 双向一致性」，措辞全部自写、零文本搬运）：
每条规则有一个**永不变更的 id**，文档与判据**互为镜像**，任一方向缺失即判红。

## 二、格式约定

### 2.1 三行结构

每条规则恰好三行（第三行可省）：

```
### ARCH.001 - <一句话说清什么被禁止 / 被要求>
- <怎么修，≤3 行，够清掉失败即可>
> [!NOTE] <为什么存在这条规则（可不写）>
```

**约束**：

- **标题行**：`### <AREA>.<NNN> - <一句话>`。破折号前后各一个空格。
  一句话必须**可判真假**（「core-agent 不得依赖 core-data」✅ /「保持架构清晰」❌）。
- **修法行**：`- ` 开头，**≤3 行**。只写「怎么让失败消失」，**不写背景、不写历史、不写辩解** ——
  背景放 `> [!NOTE]`。修法必须是**可执行动作**（「把 import 改成 X」✅ /「注意依赖方向」❌）。
- **NOTE 行**：`> [!NOTE] ` 开头，**可省**。放动机、事故出处（commit / 台账 id）、已知张力。
  这里是**唯一**允许写长句的地方。

### 2.2 分区

| 分区 | 覆盖 | 典型内容 |
|---|---|---|
| `ARCH` | 架构 / 依赖 / 模块边界 | 依赖方向、DI 组装点、行数闸门、版本钉 |
| `PROMPT` | 提示词与 golden | 提示词段落存在性、golden 样本、文案单一落点 |
| `MEM` | 记忆与数据面 | 存储契约、序列化兼容、journal 格式 |
| `DL` | 下载与完整性 | sha256 三态、锚点策略、缓冲、体积判据 |
| `TEST` | 测试口径 | `@Test` 基线、测试源集规则、离线契约 |
| `REVIEW` | **必须真人判定**的主观项 | 输出质量、UX 手感、文案语气 |

**`REVIEW.*` 显式豁免于双向核对** —— 人工项由人判、**不发检查**。
这是设计决定，不是漏洞：把主观项塞进机械判据只会逼出「为了让检查变绿而改判据」。

### 2.3 id 纪律

- 形态 `<AREA>.<NNN>`，`NNN` 为**三位数字**（`001`–`999`，补零）。
- **永不复用、永不重编号。** 一条规则作废 ⇒ id 保留并标 `[DEPRECATED]`，
  **不得**把号让给新规则（否则历史交接 / 台账里的引用会指向另一条规则 —— 这是最贵的文档债）。
- **新增分区不需要改任何代码** —— 分区是文档侧概念，只有「需要机械判据的分区」才需要写脚本。
- 一个 id 对应**一条**规则。规则合并 = 旧 id 作废 + 新 id 新建，不做「一个 id 装两条」。

## 三、双向一致性规则（核心）

> **这是本文件存在的唯一理由。** 没有这条，id 化只是给注释换个马甲。

两条判据，**任一不成立即 FAIL**：

| 方向 | 判据 | 失败含义 |
|---|---|---|
| **文档 → 脚本** | 本文件里出现的每个 `AREA.NNN`（`REVIEW.*` 除外）**必须**能映射到一条**真实存在且会抛**的判据 | 「写了规则但没人查」= 装饰性规则，会给人虚假的安全感 |
| **脚本 → 文档** | `scripts/arch-guard.sh` 里每条 `check` **必须**在本文件有一条对应 `AREA.NNN` | 「查了但没写下来」= 判据不可发现，改代码的人撞红时不知道该读哪条规则 |

**`REVIEW.*` 显式豁免**（两个方向都豁免）：人工项不发检查、也不要求脚本侧有对应。

**迁移期豁免机制**：全量 id 化完成前，第二条方向不可能全绿（61 条里只有抽样那几条有 id）。
⇒ 引入**白名单 + 计数骤降告警**（对齐 W86-06 的做法）：

- 未 id 化的 `check` 记入 `docs/16` 的「待迁移清单」（见 §五），白名单内**不算 FAIL**；
- 但白名单**只许缩不许涨**（与守卫 **#14** lint baseline「只许缩不许涨」同款纪律）；
- 白名单条数与实际未 id 化条数不等 ⇒ **判红**（防「把新规则也顺手塞进白名单」这个僵尸豁免入口）。

> **W89 D-3：本条规则已机械化（最小版）** —— `scripts/check-doc16-parity.sh`（接入
> `build.yml` 的 Unit tests job），两个冻结值 `DOC_UNMECH=4`（DL.001~004 显式声明
> `[guard] —`）与 `UNID_BASELINE=47`（61 条 check − 14 个已引用守卫号），**只许缩不许涨**。
> 已行使的判据：① 条目 NOTE 里的 `#N` 必须在 arch-guard 有「编号注释 + `check` 行」；
> ② 无 `#N` 的条目必须显式写 `[guard] —` 且计入白名单；③ 任一侧文件缺失 / 解析 0 条 ⇒ 判红。
> ⚠️ 它是**最小版**，不是本条全部：`[file]` / `[count]` / `[commit]` token 的语义核对、
> `REVIEW.*` 分区的显式豁免表、每批迁移的「白名单清零」判据仍未机械化（如实申报）。

**判据实现的硬要求**（照抄本仓既有教训，别自己发明）：

1. **行首锚形态**：解析 `### ` 标题行要 `^### [A-Z]+\.[0-9]{3} - `，不是裸子串匹配 ——
   否则正文里提到 `ARCH.001` 会被算成「有这条规则」（同 `#24` / `#28` / `#30` / `#33` 的注释位排除教训）。
2. **fail-closed**：本文件缺失 / 解析出 0 条 id ⇒ **判红**，不是静默放行
   （同 `#28` / `#32` / `#39` 的「文件缺失判红」纪律）。
3. **双向都要有反例 case**：文档侧多一条 / 脚本侧多一条，各要有一个「必红」的 selftest case
   （同 selftest「红必真命中」纪律 —— 只测绿面的守卫等于没测）。
4. **告警量级即判据**：如果这条检查会一次打印几十条，改判据而不是改输出（W86-05 的 206 条教训）。

## 四、Tokens 表

规则正文与 NOTE 里允许出现四个占位符，**它们是可解析的，不是修辞**：

| Token | 含义 | 形态 | 例 |
|---|---|---|---|
| `[file]` | 该条规则约束的**文件路径**（相对仓根，可 glob） | 反引号包裹的路径 | `core-agent/**/*.kt` |
| `[guard]` | 该条规则在 `scripts/arch-guard.sh` 的**守卫号** | `#N`；`—` = 尚未机械化 | `#1` |
| `[count]` | 该条规则的**量化阈值**（行数 / 处数 / 条数） | 整数 + 单位；`—` = 无量化 | `≤150 行` |
| `[commit]` | 该条规则**首次落地或最后修订**的 commit | 7 位短 hash | `ee3ca12` |

**为什么要有 token 而不是直接写自然语言**：双向核对脚本要能机械提取「这条规则约束哪个文件、
对应哪个守卫号、阈值多少」——写成自然语言就只能靠人读，而人读会漂。
`[commit]` 是给未来的考古者用的：`git show <commit>` 就能看到这条规则**当时**为什么被立起来。

## 五、首批迁移抽样

> **抽样不是覆盖。** 下面 9 条只做「格式示范 + 出处示范」，**不代表其余 50 条已迁移**。
> 每条都指到**真实的守卫号或台账 id** —— 写不出出处的一律不写（本仓「证据优先」纪律）。

### DL 分区（4 条）

#### DL.001 - 下载摘要算不出来时**放行**，只有摘要不符才**拒绝**

- 三态分流：`MATCH` 放行 / `MISMATCH` 拒绝转正 / `UNREADABLE` 重试一次后放行 + `warn` 留痕。
- 不要在 `UNREADABLE` 路径上加拒绝 —— 「算不出」不构成篡改证据，而拒绝要付 2~4 GB 重下代价。
- 文案必须与 `MISMATCH` 可机械区分（用户要能分清「文件坏了」和「这次没校验成」）。

> [!NOTE] 判据落点 `[file]` `core-data/.../Sha256Verifier.kt` 的 `Sha256Check` 枚举 +
> `core-data/.../ModelDownloader.kt` 的 `verifyBeforePromote`。`[guard]` —（尚无守卫号，本批迁移的新增项）。
> 台账 `W86-02`（三态分流通电）。**W86 曾把外审主张「算不出就拒绝」改成放行** —— 理由：拒绝的代价
> 是重下 2~4 GB，而引擎加载失败是可见的。`[commit]` —（见 `W86-02` 行）。

#### DL.002 - 锚点缺失必须**显式 fail-open 并留痕**，不得静默跳过

- `ModelPreset.sha256` 为 `null` 时，校验分支**不进**，但必须在诊断日志留一条可检索的说明。
- **禁止**为了「让 14/14 看起来完整」而填入未验证的摘要 —— 硬填会让主源下载被误拒。

> [!NOTE] `[file]` `core-model/.../ModelPresets.kt` 的 `sha256` 字段 KDoc（`13/14` 口径 +
> `Qwen2.5 1.5B · q8` 为什么留 `null`）。`[guard]` —。台账 `W86-09`（`parked`，重启前提 = 能取到
> HF 官方摘要）。例外事实：该条 `sizeBytes = 1597931520` vs 镜像 `1597922856`，**差 8664 B**
> ⇒ 跨源同一性代理判据不成立。见 [`docs/17-known-limitations.md`](17-known-limitations.md) L4。

#### DL.003 - 摘要必须**流式**计算，缓冲固定 1 MiB

- 用 `SHA256_BUFFER_BYTES`（= `1024 * 1024`），**不要**整文件读进内存（模型 2~4 GB）。
- **不要**在流外面再套一层带内部缓冲的包装（`BufferedInputStream`）—— 内层缓冲从未被用到，
  却让瞬时堆翻倍（名义 1 MiB、实效 2 MiB）。

> [!NOTE] `[file]` `core-data/.../Sha256Verifier.kt`（`SHA256_BUFFER_BYTES` + 类头 128× 论证）。
> `[guard]` —。台账 `W86-02`（缓冲与锚点同批落地）+ `W87-06`（去掉冗余内层缓冲）。
> **缓冲必须与锚点回填同批**：回填前校验分支根本不进，回填后才会被用户感知 ——
> 分批落地会让「回填锚点」以「下载莫名变慢几十秒」的形式被发现。`[commit]` —。

#### DL.004 - 文件体积**永远不作拒绝条件**，只作跨源同一性代理判据

- 下载完成后的体积不符 ⇒ **记录 + 继续**，不得拒绝登记（`sizeHint` 已明文裁决此语义）。
- 体积相等 ⇒ 可作「两个镜像指向同一份字节」的代理判据（配合同名同仓）。

> [!NOTE] `[file]` `feature-models/.../ModelDownloader` 的 `sizeHint` KDoc + `ModelPresets.sizeBytes`。
> `[guard]` —。台账 `W84-15`（把「体积作拒绝依据」这条死路堵死）+ `W86-02`（改用 sha256 + 独立拒绝通道）。
> 反面事故：`sizeBytes` 是**手写估算值**，硬拒会重现下载死循环（DownloadManager 说下完了，
> 我们因体积不符拒绝 ⇒ 用户重下 ⇒ 再拒）。`[commit]` —。

**每批的完成定义（同一句，不许改）**：

> **双向核对守卫上线且全绿** —— 文档里有而脚本不抛 = FAIL；脚本抛了而文档没有 = FAIL。
> 「抽样写完」不算完成，「白名单缩短」也不算完成，**只有白名单清零 + 两向 0 缺口才算**。

**明确不做的事**（避免范围蔓延）：

- **不重编号**已存在的守卫 `#N` —— 守卫号是历史交接与 selftest 的引用面，重编号 = 制造悬空引用。
